# ADR-008: Publish Generated Reference Documentation Through GitHub Pages

Date: 2026-09-23

## Status

Accepted

## Context

ADR-004 established reproducible Doxygen reference generation beneath
`doc/reference/` and deliberately deferred public hosting until the generation
contract was reliable.  The repository now has that contract: `make docs`
validates the maintained Bash documentation, regenerates the ignored Doxygen
output, and verifies that `doc/reference/index.html` exists.

Bootstrap already uses a thin GitHub Actions Pages workflow that prepares
repository dependencies through Make, invokes `make docs`, verifies that the
generated documentation remains disposable repository state, and publishes only
the generated reference tree.  The same pattern fits `routeros_ssl` without
changing its build, runtime, release-artifact, or source-control contracts.

## Decision

The repository SHALL publish the HTML generated by `make docs` through GitHub
Pages using `.github/workflows/static.yml`.

The Pages workflow SHALL:

1. run on pushes to `main` and on explicit `workflow_dispatch`;
2. use only the permissions required to read repository contents and deploy to
   GitHub Pages;
3. install the system documentation prerequisites required by the existing build;
4. run `make deps` followed by `make deps-check` before documentation
   generation;
5. invoke the canonical `make docs` target rather than duplicating Doxygen
   behavior in workflow YAML;
6. verify dependency state again after generation;
7. require `doc/reference/index.html` to exist and remain ignored;
8. require documentation generation to leave the tracked checkout clean;
9. upload only `doc/reference/` as the Pages artifact; and
10. deploy that artifact through GitHub's Pages actions and the `github-pages`
    environment.

The workflow SHALL use the same pinned Pages action revisions as the Bootstrap
reference workflow at the time this decision is accepted.

The workflow SHALL NOT commit generated Doxygen HTML, create a `gh-pages`
branch, alter release artifacts, or change `make docs` dependency-acquisition
semantics.  Repository Pages settings remain hosting configuration rather than
maintained source; the repository must be configured to use GitHub Actions as
its Pages source for deployment to succeed.

## Alternatives Considered

### Commit generated Doxygen HTML

Rejected for the same reason established by ADR-004: generated HTML is derivative
state.  Committing it would create review noise and another representation that
must remain synchronized with maintained source.

### Publish from a dedicated gh-pages branch

Rejected because the Pages artifact workflow publishes generated output directly
without introducing another long-lived branch or source-of-truth surface.

### Add deployment steps to validate.yml

Rejected because validation and privileged publication have different triggers,
permissions, and responsibilities.  Keeping Pages deployment in a dedicated
workflow preserves the existing validation contract and keeps publication
permissions narrowly scoped.

### Reimplement documentation generation in GitHub Actions

Rejected because ADR-002 establishes Make as the repository interface for
documentation operations.  CI should prepare dependencies explicitly and then
invoke `make docs`, not duplicate bash-doxygen or Doxygen commands.

### Install Graphviz to match Bootstrap exactly

Rejected because `routeros_ssl` currently sets `HAVE_DOT = NO` in its
`Doxyfile`.  Installing an unused rendering dependency would add package
acquisition without changing generated output.

## Consequences

Reference documentation becomes publicly deployable from every merged change to
`main` and can also be redeployed manually.  The published bytes remain
reproducible derivative output from repository source and prepared dependencies;
they do not become maintained source.

The Pages workflow gains narrowly scoped `pages: write` and `id-token: write`
permissions, while ordinary validation remains read-only.  A repository whose
Pages source is not configured for GitHub Actions will require that one-time
repository setting before the deployment job can succeed.

ADR-004 continues to govern documentation generation and ignored output.
This ADR adds the public hosting contract that ADR-004 explicitly deferred.
